# Kerdion - Topology Streams & Real-Time Metrics Payload (Phase 4C)

## 📌 Overview
Phase 4C focuses on optimizing the network output and delivering the highly complex data structures generated by the ML engines to the frontend. This phase successfully exposed the ST-GNN's internal market topology (adjacency matrix) for visual rendering and radically restructured both the REST API and the WebSocket Pub/Sub streams to broadcast a unified, multi-model comparative dictionary.

## 🏗️ Tech Stack Adjustments
* **In-Memory Caching:** Redis (`redis.Redis`, `redis.asyncio`)
* **Data Serialization:** `json`
* **Schema Validation:** Pydantic (`BaseModel`, nested dictionaries)

## 🚀 Key Features Implemented

### 1. Adjacency Matrix Topology Cache Strategy (`app/services/ml_inference.py`)
* Prevented severe resource starvation by extracting the $10 \times 10$ learnable spatial topology array (`learned_adj`) directly during the ST-GNN's forward pass.
* The raw tensor is converted to a NumPy array, serialized to JSON, and cached synchronously into Redis under the key `kerdion:topology:latest`.
* **Why it matters:** This allows the API to serve the heavy structural matrix on demand instantly to thousands of clients without ever waking up the GPU or CPU for redundant neural network execution.

### 2. REST Topology & Metric Endpoint Construction (`app/api/v1/endpoints/predictions.py`)
* **`GET /api/v1/predictions/topology`**: A new endpoint that bypasses PostgreSQL entirely, reading the adjacency matrix directly from the Redis cache. This provides the raw structural vectors perfectly formatted for frontend heatmap components (e.g., Seaborn-style charts).
* **Roster JSON Restructure (`GET /api/v1/predictions/{pair}`)**: Upgraded the standard pair endpoint. Instead of returning a flat list of repetitive DB rows, the endpoint now groups all records by timestamp. It leverages new Pydantic schemas (`RosterResponse` and `ModelRosterMetrics`) to return a clean, nested dictionary grouping the 3-model roster output alongside their QLIKE and Confidence Interval performance data.

### 3. Worker-to-WebSockets Pub/Sub Architecture Expansion (`app/worker/tasks.py`)
* **Expanded Prediction Pipeline**: The Celery task (`_run_prediction_pipeline`) was upgraded to run inferences for all three models (GARCH, GRU, ST-GNN) simultaneously. 
* **Dynamic Metric Generation**: Integrated the `loss_engine.py` utilities into the worker. The pipeline dynamically calculates a proxy error distribution based on recent market turbulence to feed the 95% Confidence Interval engine.
* **The Unified Payload**: The worker now fetches the latest Diebold-Mariano test result from Redis, bundles it with the three models' predictions, QLIKE estimates, and CI bounds, and constructs a massive JSON roster payload. This highly-structured packet is published to the `live-predictions-channel` across the WebSocket layer every 15 minutes.
