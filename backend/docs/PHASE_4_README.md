# Kerdion - API & Data Delivery (Phase 4)

## 📌 Overview
Phase 4 focuses on securely and efficiently delivering the predictions generated by the ML Engine to the frontend clients. We transitioned from temporary test scripts to a production-ready API architecture, implementing strict Pydantic data validation, CORS middleware for frontend communication, and a real-time WebSocket streaming system powered by Redis Pub/Sub.

## 🏗️ Tech Stack Additions
* **API Routing:** FastAPI Routers (`APIRouter`)
* **Data Validation:** Pydantic (`BaseModel`, `ConfigDict`)
* **Real-Time Streaming:** WebSockets, Redis Pub/Sub (`redis.asyncio`)
* **Concurrency:** Python `asyncio` background tasks

## 🚀 Key Features Implemented

### 1. RESTful API Architecture (`/api/v1/`)
* Structured the API into versioned endpoints (`app/api/v1/endpoints`).
* Configured `CORSMiddleware` to allow cross-origin requests from the upcoming Next.js frontend.
* **`GET /api/v1/predictions/`**: Fetches a paginated history of all predictions.
* **`GET /api/v1/predictions/{pair}?hours=24`**: Fetches chronologically ordered predictions for a specific coin over a given time window. Perfect for rendering line charts (e.g., Recharts/Chart.js).

### 2. Pydantic Schemas (`app/schemas/prediction.py`)
* Implemented `PredictionResponse` schemas to safely serialize complex SQLAlchemy ORM objects into clean, standardized JSON format.

### 3. Real-Time WebSockets (`ws://.../api/v1/ws/live-predictions`)
* Built a `ConnectionManager` to track all active frontend users connected to the platform.
* Leveraged FastAPI's `lifespan` context manager to spawn a permanent background `asyncio.Task` that listens to the Redis `live-predictions-channel`.
* **The Real-Time Bridge:** When the Celery worker finishes a calculation, it publishes a JSON payload to Redis. The FastAPI background task instantly intercepts this and broadcasts it through the WebSocket to all connected browsers.

## 📡 End-to-End Data Flow
1. **Worker (Publisher):** `tasks.py` -> PyTorch Inference -> Save to DB -> Publish to Redis.
2. **API (Listener):** Redis Pub/Sub -> FastAPI Background Task -> `ConnectionManager.broadcast()`.
3. **Client (Subscriber):** Next.js Frontend -> Updates state -> Re-renders chart seamlessly.
